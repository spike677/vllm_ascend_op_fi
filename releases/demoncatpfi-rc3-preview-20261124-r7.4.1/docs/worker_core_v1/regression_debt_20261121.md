依据冻结r2的 regression-review.json 和当时 current 运行原记录。199项failure + 11项error 是210次失败事件，对应184个不同ID（部分参数化/重复执行的ID相同）；不能按集合长度184漏掉26次事件。完整清单见同目录 `regression_debt_20261121.json`，每条保留事件序号、ID、测试文件、分类、后续动作及原失败尾部SHA。分类器可从原记录重新生成。

|分类|事件数|处理|
|---|---:|---|
|已废弃的公共研究工厂选择|8|两方法的8个子用例，明确skip原因；Native实现保留，普通入口准入负向测试保留|
|环境|5|子进程相对PYTHONPATH失效，ModuleNotFoundError；需要修正后复测|

“真实欠账”不等于197个产品注入缺陷。大部分在prepare准入处失败，未执行后面的所有权、消费者、恢复测试。必须修复夹具或测试入口后重新跑，后续暴露的实现缺陷再单独定性。26 residual退出交付也不意味着其通用租约/恢复断言可以一起删除。

此次仅将两个已经失去公共含义的研究工厂选择测试标记skip。其余未假报修复，清单 resolved=false。RC3相关测试全部通过仍是后续完整冻结的门禁；本次不会据分类结果冻结r3。

复核补充：210条均已定位到实际存在的测试文件；110条能从原记录提取具体拒绝代码，保存为 `observed_rejection_codes`，其余不得凭相邻失败推断原因。该清单是分类与修复队列，并非197项已完成根因定位。需修复的实现缺陷与测试夹具缺陷将在复跑后继续拆分。
