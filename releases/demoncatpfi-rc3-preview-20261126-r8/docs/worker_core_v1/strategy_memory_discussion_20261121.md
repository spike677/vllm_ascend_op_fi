## 2. 公共层划分（设计，尚未落地）

沿用现有生命周期、request_plan、效果摘要、租约和多 rank 协调，不新增独立状态机。

|层|职责|边界|
|---|---|---|
|engines / A1 region_rewrite|torch 数值、特殊值或区域覆盖|实际张量存储动作，不自动证明原 kernel 越界|
|engines / A2 Native memory|有界显存读写、备份、顺序、恢复|只在已验证活跃对象的合法范围内写入；不接受任意裸地址|
|engines / B index_perturb|torch 索引扰动|positions、路由、槽位语义由 site 提供|
|engines / C reference_recompute|torch attention、dynamic quant、matmul 参考重算及替换|错误规则、输入布局、真实消费者均需披露|
|sites|模型/算子结构发现、真实调用、对象归属、消费窗口和适用性|自动选点不等于所有模型已适配|
|现有任务框架|请求作用域、rank 决策、阶段、失败恢复、准入|TP1 只作为 world_size=1 的 CPU 控制路径|

拟议 sites：norm、linear（普通/量化投影）、attention（FIA、MLA 吸收形式、稀疏 MLA）、rope、moe_unpermute、kv_writer、dynamic_quant、residual_add。模型顺序为 Qwen 混合注意力、V2-Lite、V4.1；不能将 GQA 的布局或 softmax_scale 直接套到 MLA。

“只依赖 ACL 公共接口”仅适用于显存原语层的目标，不适用于整条调用链。allocator 快照依赖 torch_npu，tensor/stream 绑定依赖框架，KV/MLA/消费者依赖运行时；具体公开接口及版本需在实施前核对，不在此声明已兼容所有版本。

## 4. 邻接与定向区域：讨论结论

可以公共化“真实存储区域改写”，不应把 allocator 邻接作为所有内存故障的统一前提。建议显式分开：

1. `semantic_region`：site 绑定正在存活的 residual、输入或缓存区域，定向改写。可稳定复现该区域被污染以及真实消费者传播。
2. `adjacent_live_region`：从 writer 的真实分配块边界发现地址紧邻的活跃块，并证明对象归属和下游消费。无目标时返回“当前部署无合格邻接”，不静默降级到模式 1。
3. `kv_layout_region`：由真实 KV 布局计算列、槽位、页及有效字节，不要求跨分配块邻接。
4. `argument_redirect`：在真实调用边界替换输入/输出引用；这需要对应参数接线，不能只靠内存复制实现。

以上为建议接口含义，不是已注册配置键。不能让用户填层名或裸地址；由 site 和部署范围自动绑定。

严格邻接只证明同一设备地址空间的连续可访问区域，不证明物理 HBM 页邻接。必须分别记录逻辑张量范围、storage 范围和 allocator block 范围；view 的 offset/stride、对齐 padding、空闲块、workspace、待释放块不能混为有效消费者区域。

不得为制造邻接而移动/重新分配模型张量；不得从某块末尾盲目向未知区域写入。受控地写入已确认邻接目标，证明的是邻接污染动作，不自动证明原 kernel 自身执行了越界指令。

## 5. Fault20 的复现范围

|变体|原输入内容/指针|可证明的效果|不能据此宣称|
|---|---|---|---|
|输入内容覆盖|指针不变，内容临时来自另一活跃缓冲区|真实算子读到错误内容并传播|地址槽被替换、原输入未被修改|
|输入引用替换|原输入内容保留，消费者参数绑定另一存储|真实算子从错误来源地址读取|与内容覆盖有相同的别名副作用|
|原 ABI 地址槽机制|按已登记版本接线|该固定组合上的地址替换证据|新栈天然兼容|

因此“20 的内存级变体支持复现效果”可以成立，但须标明采用哪一动作。首版内容覆盖可以复用 A2；若验收承诺是读错地址，必须完成真实参数重绑定，不能用内容覆盖替代验收。

顺序要求：备份完成 → 污染完成 → 消费者设备读取完成 → 在独占恢复窗口恢复。Python 返回不作为设备读取完成证据。首版可只支持可证明的同 stream 顺序；跨 stream 必须有明确依赖。

## 6. “会触发的位置均触发”：新增建议，尚未替换单 rank 单点契约

建议定义为：在声明的 rank 集合、请求作用域和已适配 site 内，对本次真实执行到的全部合格调用持续触发。

- 一个设备故障：只在自动选中的 rank 上每次匹配触发，其他 rank 守卫并观察传播。
- 公共软件缺陷：所有 rank 在实际满足同一条件时触发；没有对应调用的 EP rank 不制造额外调用。
- 调用频率和 rank 范围独立：单 rank 不等于只命中一次，多 rank 不等于每 rank 命中数相等。
- 故障可能改变 MoE 路由，不能冻结 baseline 的调用列表作为 fault 必须出现的静态列表。
- 条件性命中点不插入临时全组 collective；协调留在各 rank 都会到达的控制边界，避免调用数不等导致死锁。

覆盖摘要至少含：observed、eligible、attempted、applied、changed、consumed、restored、failed 及不适用原因。适配器覆盖不到的调用必须披露，不能用“没观察到”证明全覆盖。eligible 中执行失败或备份不足不能藏到正常 skip 后宣称全部触发。

“写入成功”和“新增数值变化”分开；上游已写 Inf 时，下游再次写 Inf 可能没有新增变化。不得删掉旧变体有限值前提而沿用其通过结论。

增量工作主要在可复用公共框架：重复命中租约、对象生命周期/地址复用、重叠区域冲突、设备完成依赖、失败恢复及多 rank 汇总。EP 还增加专家分布和动态请求归属；不承诺仅改一个 every_match 开关即可完成。无需因此恢复历史全目标 C2/C3 或要求 token 改变。

## 7. 恢复契约

- 租约绑定对象、分配生命周期、作用域、device 和字节区间；地址复用后不能向新对象写回旧快照。
- 持有对象引用直到消费和恢复完成；可观测的活跃标志不能替代生命周期所有权。
- 重叠注入必须明确串行/拒绝规则；恢复不能覆盖之后正常算子的合法原地更新。
- 输入临时覆盖需可独占消费窗口；residual/KV 若会继续正常写入，site 必须提供安全恢复或干净请求状态重建边界，否则当前调用不适用。
- “注入区域字节恢复”“租约资源清零”“OFF/health 干净请求结果精确恢复”分别验收。恢复输入不撤销已传播到输出/KV 的污染。
- 不额外承诺将同一个已污染生成请求恢复到从未注入的轨迹；这可能需要重算/缓存重建。

## 8. 实施顺序记录与本轮暂停点

负责人给定的普通主线：39op → Batch torch → 28 大误差（MLA 提前）→ 39mr → 33。
Native 内存支线：显存原语和邻接 CPU 测试 → 26 residual → 41 → 26 FIA → 20；先 Qwen，再 V2-Lite 的对应布局。
V2-Lite 新栈 TP2：28 MLA → 8 → 18/22/39op。M4 TP8+EP 的设计与 CPU 实现推进专家分布、单目标 rank、跨 rank 汇总及恢复。

两条支线合并排队时仍需一份明确矩阵；这次不据讨论自行改任务队列。暂不启动新 NPU 验收。

讨论后需收敛的三个选择：
1. A2 新栈主路径是否允许定向语义区域，同时把严格邻接保留为独立模式（建议允许）。
2. 全匹配首版是单目标 rank 的 every_match，还是新增全 rank 软件缺陷变体（建议先前者，再独立验收后者）。
3. Fault20 本轮承诺输入污染，还是必须复现实际错误来源地址（建议两个名字/两份效果契约）。
