# 33 A3 补充取证：先闭合观测，不执行注入

现有材料：sparseMode=3；7928 条记录、最大 serial=8191；捕获有截断；对应 serializer 源码缺失。
不能用 sparseMode 推断 scheMode 或 S2；不能用最大 serial 减条数直接宣称丢失多少次，因为起点、重复与过滤尚未证明。
A3 入口继续关闭。以下由负责人转交，优先处理现有原件，不要求先重跑注入。

1. **捕获完整性**：从原始日志取出真实 serial，报告记录总数、唯一 serial 数、最小/最大值、重复清单、区间缺号。
   同时给出过滤条件、buffer 容量、丢弃计数、capture_start/stop、进程/rank 区分方式。没有记录的字段填 null。
   缺号只能说明该捕获集合不连续，不能单凭它归因于某次 kernel 未执行。
   原件分段导出，每段≤4KB，含段序号/总段数、条数、字节数和 SHA；整件字节数/SHA 独立记录。
   如果原件本身已截断，已有证据不能恢复。下一轮只读观测扩大/分段轮转容量并逐段校验，不复用截断样本做验收。
2. **字段来源**：每个实际 launch 保留 tiling key、blockDim、实际 S2 分组、shape、dtype、layout、序列边界，
   sparseMode 与 scheMode 分开列；标明是公共 POD、真实 raw、host 派生还是不可观测。不得拿期望 profile 补实际值。
3. **serializer 与构建身份**：提供实际 CANN/operator 包版本、host 库 SHA、来源提交、对应 serializer/tiling struct 源文件 SHA、
   字段偏移/类型/长度、构建 receipt SHA，以及该源文件到当前二进制的对应依据。只有版本标签不足以证明结构布局相同。
   没有匹配源码时标为“raw 分组未证明”，禁止猜偏移；可先保留公共 POD 与原始 raw 的长度/SHA。
4. **控制门槛**：完整观测与 serializer 对应通过后，固定同一真实 Q/K/V、mask、KV 页/slot映射和合法 key 集合，
   用 A3 实测分组做无故障控制重算；完整目标输出逐位一致比例至少99%。不从最终输出选择局部通过元素。
5. **决定**：全部满足后才进入两个作用域的产品注入验收；未满足继续关闭，给出具体缺项。
   A2 的分组与通过结果不能替代 A3 的上述链条。

黄区原件仍保留黄区。回传按已批准文本协议，用分段提取与 SHA 对应原件；本说明不主动发消息或启动黄区任务。
