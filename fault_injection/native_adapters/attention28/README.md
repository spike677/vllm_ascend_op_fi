# Fault28 source integration

The source-only import is recorded in `source_import.json`. No old vendor,
private tensors, new statistics or build qualifications are imported.

## FA

`native_execution_strategy/native/` contains the actual host bridge, typed
selector, POD decoder, source patcher and CPU tests from Git commit
`6dad85c480255829b0a4e74657a7e2ff2ce390b3`. Every imported byte has a source SHA.
The historical build/stage scripts retain their original paths for audit;
they are not a portable Native Build Manager recipe. New deployments still
need a reviewed isolated build and real launch verification before admission.

## FIA

The public entry is `fia/apply_policy.py`, with explicit `--variant
legal_tiling` or `--variant denominator_replay`. It requires a clean, private
checkout of ops-transformer commit
`c77c0829f1f0f0b8f882db1d9b051a758b605472`. `fia/base_policy.py` is the
byte-preserved derivation input, not the final coupled/replay patch entry.

The patcher checks every source anchor before writing. It derives native host
M/S2 loops and tails before the subsequent original tiling stages. Legal mode
uses healthy causal-tail keys. Replay mode adds a distinct BRC template and
key `119000000000400000`: at the second S2 block it repeats the first block's
existing denominator mass. It does not alter Q/K/V, numerator/PV, output writes
or precision types. Legal and replay are separate mechanism selections.

Unlike the old relink driver, this entry does not depend on a previous
experiment's `.o` files. All host dependents and matching kernels must be
rebuilt from the patched checkout. Its result is explicitly
`PATCHED_NOT_BUILT_NOT_NPU_VALIDATED`.

Current declared execution geometry remains the existing exact guarded FIA
scope, B1/B8, FP16, Hq16/Hkv8, Q/KV2048 and D128 on the matched 9.1/A2 package.
Extra constants or modes in historical source are not new supported shapes.
No VENDOR_SHA or launch gate in `fault_injection/fia.py` has been relaxed.

`fia/build_fresh.py` supplies a source-specific full rebuild recipe. It copies
only committed dependency sources and pinned source archives into a fresh
attempt, rebuilds the entire host package, restores missing JIT include paths
from that same new source, then compiles the matching keys with OPC. Its kernel
input must be generated by the new build. Neither old object files nor the old
`lib_cache` are consumed. Run it in a CPU-only, network-disabled aarch64 CANN9.1
container after sourcing the SDK environment; SDK interfaces and offline
dependency contracts are checked, and missing dependencies fail with evidence.
The pinned opbase commit includes fourteen `.o`-named dummy files under its
tests directory. These exact paths, Git blobs, byte lengths and SHA256 values
are listed in `build_contract.json`. Only the new clone's matched fixtures are
removed before configure; the input dependency tree remains unchanged. Unknown
objects or changed bytes still fail. The actual configure must keep tests OFF,
and excluded files must not reappear before completion. The removal receipt
is `evidence/excluded_test_fixtures.json`.

```sh
python build_fresh.py --source /new/patched-source \
  --policy-receipt /new/patch/policy_source_manifest.json \
  --dependencies /readonly/dependencies_a4 --work /new/fresh-build \
  --sdk /usr/local/Ascend/cann-9.1.0 --python /usr/bin/python3.11
```

The output remains `CPU_BUILD_ONLY_REQUIRES_NATIVE_QUALIFICATION`, with loading
disallowed. The recipe is not a new artifact certificate and does not relax
the existing runtime SHA gates. Current remaining gates are successful actual
fresh build, new artifact binding, actual raw/POD/launch equality, independent
single-target B/F/OFF and public Worker qualification. Source availability,
CPU patch checks, and CPU unit tests alone do not close those items.
