## Mechanism and contract boundary

The original `17.spatial_padding` mechanism is unchanged. At the real Torch
Conv3d call, B passes padding `[0,0,0]`; F passes `[0,7,7]`. The same underlying
operator executes once. The adapter requires a nonoverlapping patch16 kernel,
stride equal to kernel, matching complete input/weight/bias values, unchanged
output geometry, and unchanged input/weight/bias after execution. It does not
edit outputs, crop/pad results, add a layer or select a user-supplied layer name.

The execution-adapter contract permits a lightweight Conv parameter adapter.
Qualification here is **the real Torch parameter boundary**, represented by the
actual module callable and schema under existing `python_hook` transport.
Final Torch dispatch is explicitly not ACLNN arguments or device launch:
`aclnn_launch_arguments`, `device_payload_observed`, `native_qualification`, and
E5 remain false. Diagnostic full-value hashes are not msprobe statistics/mix.

`ActualVision17Request` installs an independent upper observer, the original
adapter, and an independent lower observer within the actual visual call.
The upper observation supplies each request's denominator before admission;
the lower observation proves the arguments that reach Torch and the exact live
returned-object chain into the first numerical consumer. Unknown first readers,
missing calls, changed request objects and cached skips refuse qualification.
The old adapter's storage-ID consumer list does not prove consumer propagation.

The actual Worker request binding reuses source-checked scheduler feature,
placeholder, image/grid bytes, visual arguments and root/logits lifecycle.
Every phase must contain a newly observed encoder invocation. Public MM cache
reset is only cache control; actual `scheduled_encoder_inputs` must still match.

## Public protocol and scope

The new typed `Vision17GroupBinding` is inert deployment state. The root can add
an optional registry route for `17.spatial_padding` plus that exact binding to
`Vision17GroupProvider`; the observation-only route remains separate. No shared
registry, exporter, Host or Runtime implementation is modified here.

The provider reuses WorkerFaultRuntime owner/generation and CoverageSession's
independent observer, target reservations, live C2 proof, admission receipts and
recovery barrier. No `execute_model` replacement or background replay is added.
Only already-enqueued requests execute. An operator hit, its numerical effect,
and whole-model/logits propagation are separate evidence fields.

| Phase | Adapter | Required evidence |
| --- | --- | --- |
| `native_baseline` | absent | Actual initial/final arguments and consumer, complete encoder/hidden/logits |
| `baseline` | pass-through | Same complete result as stock, establish input/reference hashes |
| `baseline_repeat` | pass-through | Exact repeated healthy result and denominator |
| `lossless` | pass-through | Same output through installed adapter, actual source/object binding |
| `c2_fault` | once per discovered target | Actual changed padding, changed Conv output and first consumer |
| `c2_off` | absent | Complete exact restoration, zero owned hooks/modes, group release |
| `c3_fault_0/1` | every actual match | Original live C2 proof; every request hit; exact fault repeat |
| `c3_off` | absent | Complete exact restoration and release |
| `cleanup_healthy` | absent | Same Worker, actual encoder, exact output after fault resources released |

This checkpoint admits exactly one independently discovered eligible projection.
The successful once-F/OFF pair establishes C1 at that live boundary and the
C2 all-eligible set of cardinality one. It does **not** prove several targets:
`multi_target_verified=false`; more than one projection refuses before F until
separate multi-projection C1 adaptation is provided. Runtime source admission
is the reviewed Qwen3-VL Worker implementation; other models are not implicitly
qualified merely because their weights have the same dimensions.

On a failed attempt, error receipts survive cleanup. Once a coverage group is
open, unregister cannot release its scope without a real newly enqueued OFF
and healthy request. Unknown/foreign hooks or modes retain ownership until
actual restoration. A failed group can recover cleanly while its contract
remains failed; it is never retried automatically as successful qualification.

## CPU verification and root handoff

38 CPU contracts pass: 7 independent trace, 10 context, 9 observation-only
Host/Runtime, 12 group Host/Runtime. Negative cases cover cached healthy/F calls,
unknown first consumers, actual padding not changed despite admission, failure
after F, absent OFF, foreign hooks, settings that try to bypass healthy phases,
equal-weight visual replacement, and read-only query behavior. Both new probe
entrypoints compile.

The root-owned `vision17_cache_control.reset_idle_mm_cache` must explicitly
accept the real group phase names before execution. This checkpoint never
mislabels F as a healthy phase to bypass that helper, and does not edit its
implementation. The group probe refuses if the helper or typed registry route
is not integrated.

No existing raw reports, the source72 census, or Fault8/18/22 results are changed.
