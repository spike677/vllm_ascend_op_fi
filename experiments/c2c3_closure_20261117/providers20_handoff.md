# Fault20 native target groups

This is a new bounded v3 adapter. Existing C1 v1/v2 uniqueness and healthy-input
byte equality are unchanged. CPU tests and an SDK build do not establish C2/C3.

`QuantGroupBackend` observes every actual public dynamic-quant/QMM chain and
reconciles every QMM native Run against the always-on native inventory before
admission. Two healthy requests freeze module/call-site, current typed formals,
cache registration lifetime, Worker/process lifetime and build identity. A
native target is qualified only after its own reference, D2D lossless execution,
and exact input/output OFF readback. Unresolved structural candidates remain
blocking rows; the 135 public candidates are never relabelled as 135 native
targets without actual evidence.

The whole actual root and true LogitsProcessor remain intact. The probe uses
the natural prompt `Hello.`, requires 1–4 actual tokenizer tokens, and runs
fresh prefill with one request per phase. This keeps the existing 65,536-byte
native x1 guard without broadening native semantics. It makes no decode claim.

The v3 native group seals exact target keys. Each admitted call gets one native
continuation and one target lease. The original source allocations are read
back unchanged. Propagated fault-phase values may differ from healthy reference
values; actual transformation/readback and exact target identity are still
required. Full target OFF, disabled OFF, all-stop/all-drain, callback release,
owned-hook removal and same-Worker full-logits equality precede the C2 proof.
Only that live proof can open C3. A missing/failed target never passes coverage;
an uncertain native failure remains quarantined rather than claiming recovery.

```sh
R=/home/17-fault-c2c3-20261117
SOURCE="$R/<fresh-source-snapshot>"
INSTALLED="$R/<fresh-installed-packages>"
NATIVE="$R/build20-v3-a1/cache/8a2d105afe73c31e2184069455538d11f399900c05e4e455aedb366aa481b35c/attempt-13a8166e1df347a7898110ea0456b504/native"
python3 "$SOURCE/experiments/c2c3_closure_20261117/providers20_stage_group_bundle.py" \
  --native "$NATIVE" --cpu-receipt "$R/providers20-cpu-a3/contract/receipt.json" \
  --out "$R/native20-group-a1"
python3 "$SOURCE/experiments/c2c3_closure_20261117/providers20_prepare_group_case.py" \
  --installed "$INSTALLED" --native "$R/native20-group-a1" \
  --probe "$SOURCE/experiments/c2c3_closure_20261117/providers20_worker_probe.py" \
  --build-sha 0c3e3f5fc73401f7b6e9bcdba261c730cf8ba17d6389c90a3843399da6b3df30 \
  --source-commit <integrated-commit> --card <root-reserved-2-or-5> \
  --statistics --c3 --out "$R/providers20-group-a1-cases.json"
```

The stager refuses mismatched CPU source hashes, failed checks, changed build
artifacts, or an existing output directory. The root may add its verified
identical-byte mapped-library snapshot with `--mapped-libraries`. Queue only
through the shared root resource lock and preserve failed attempts. No new
native build is needed for the Python glue because the ctypes/native source
fingerprint remains the already built v3 source.

The queue manifest fixes the DeepSeek model, vLLM 0.18.0 image, CANN 8.5.1,
TP1/rank0, <=80 GiB memory, <=16 CPUs and <=1800 seconds. All inputs are read
only. Each group additionally caps 512 targets, 4,096 public API calls, 16,384
native continuations and 1,200 seconds. Statistics capture full baseline step
5 and fault step 6. E5 is separate raw B/F comparison with fixed
`rtol=1e-5, atol=1e-8`; NaN, null and alignment failures remain visible.

CPU coverage includes actual two-projection CPU calls sharing a simulated
native cache but receiving distinct leases, live C2→C3 scheduling, whole root
and logits hooks, disabled observer counts, missing native callbacks, cache
epoch drift, unresolved candidates, late public-return lineage failure, and
prior C1 tests. Every simulated result carries `cpu_contract` and cannot count
as real Worker evidence.
