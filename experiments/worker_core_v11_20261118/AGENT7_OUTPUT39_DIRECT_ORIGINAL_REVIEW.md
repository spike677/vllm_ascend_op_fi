# Output39 direct-forward and partial-group original audit

The saved-original reviewer now understands the current direct-forward
observation format and bounded Ascend Rotary helper non-call proof. It imports
no model, provider or Native library, performs no device or network work, and
always reports `c2/c3/e5/public_qualification_granted=false`. A consistent saved
report is historical evidence for the root reviewer, not a new capability.

The new [pure frame auditor](review39_forward_originals.py) requires actual
request/inventory joins, complete frame order and successful non-null returns,
the held model/Worker/owner/generation/thread, and stable bound function/code/
globals identities. A direct frame's file hash must match the frozen model
source manifest. It retains explicit binding gaps; a missing direct frame
cannot be replaced with an unchanged observed-module count.

The Rotary exclusion is restricted to the reviewed Ascend source SHA
`74653da7274de182e8497f7d6b07ea7c6deeeef21e710e34eed5a349b0f671e7`,
`AscendRotaryEmbedding.forward_oot`, and the precise saved
`vllm.npu_rotary_embedding.default` schema. It reconstructs both complete alias
sets, joins every returned delegate frame to one actual API return, checks the
full operator count, and confirms the helper appears in neither actual module
calls nor frames. Both healthy inventories and every group forward must agree.
The structural row's reason string or zero helper-call count alone cannot pass.
External model files are not reread: these source joins use the original frozen
runtime manifest plus the rehashed observation implementation.

The group provenance check now includes `serving39_output_discovery.py` in its
expected loaded module set and the full current implementation hash set,
including `call_binding.py`, `identity.py` and `environment.py`. The CLI output
also pins its exact input result and the new helper. Existing private originals
remain unchanged.

Failure handling preserves stage boundaries. The reviewer reads completed
normal **and recovery** request originals, allowing a failed request to remain
explicitly absent from the completed-return prefix. It audits the full C2
denominator, effects, OFF, health and original live-proof issuance when that
group completed before a later C3 failure. A recorded consumption of that exact
object can be reconciled without claiming C3 execution succeeded. The result
remains `FAILED_OR_PARTIAL_NOT_QUALIFIED`, retains original errors and recovery
errors, and sets whole-group completion false. Provenance failure also prevents
the completed-C2 consistency indicator from passing. No Native finite-value
guard, Runtime transition or producer success flag was changed.

Validation uses the **current producer** through actual CPU Torch frames,
public Host/Runtime RPC and ordinary enqueues. Its test-only Rotary source and
CPU operator schema are explicit and cannot be used in natural mode. Tests
include a complete C2/C3 run and a real exception at the first C3 F followed by
actual recovery. Negative cases remove frames or API returns, alter source,
delegate, owner, schema, aliases and proof identity, mark a called helper as
uncalled, or leave only the reason string. Mutations touch audit copies only.

```text
PYTHONPATH=src;fault39/src;.;tests;tests/worker_extension
TORCH_DEVICE_BACKEND_AUTOLOAD=0
python -B -m unittest test_worker_core39_direct_original_review test_worker_core_group_original_review -q
```

All **57 tests passed** in 22.406 seconds on the local CPU environment after
adding rejected-Native-apply joins and explicit Native byte-pin provenance.
The final command also includes `test_output39_group_native_provenance`.
This replaces, and is not added to, the earlier overlapping 44/47-test runs.
The exception-path hook warning is expected by the failed-C3 fixture.

For a rejected Native apply, the partial reviewer separately joins the original
failed enqueue/abort, target and actual partial projection, exact owner,
generation, thread and span, followed by the original open/apply/restore/release/
live event sequence. A claimed `POSTWRITE_APPLY_n` error requires an actual
nonzero return with that code. A rejected apply with zero changed elements is
not a hit. The report records successful release when observed but does not
infer the selected original tensor value or compiler provenance from an error
number. The extra failure-schema unit fixture is explicitly CPU-only; the
actual NPU result still requires running the CLI over full pinned originals.

## Explicit Native identity for the group audit

The first source84 original review retained 106,972 checks with no top-level
original-consistency issues, but its provenance correctly remained false. The
legacy C1 helper expected the old fixed DSO SHA
`8876f2b99e70a9df8201b6ae0ace2cc4be8702afcf6703f9b72d1dda3bc26622`.
Both the new probe and the inert deployment readback instead identified
`2e7f1bb9b957afa9ab1ef14da4aa802608d51234d736cefa93ecc765dde461d7`.
Consequently `NEW_WORKER_ENTRY_AND_EXACT_NATIVE_DSO` and
`INERT_TRUSTED_NATIVE_DEPLOYMENT` failed; the 32 source-file and 58 group-source
checks did not fail. The retained first report SHA is
`95e04af081e1626638fc1ab898e060582ae4b104251f4bc8f7d1768dfce6e7c1`.

The group CLI now accepts an explicit external byte pin:

```text
--native-sha256 2e7f1bb9b957afa9ab1ef14da4aa802608d51234d736cefa93ecc765dde461d7
```

It never selects that expected value from the probe. The actual library bytes,
the external pin, probe field and deployment readback must all agree. Omitting
the argument retains the fixed legacy C1 pin and rejects this newer library.
The legacy C1 file remains unchanged, and its in-memory defaults are restored
after each group review, including exceptions. All original source-file,
loaded-source and worker joins still execute.

Additional guards require the actual group schema, mechanism, `c2_once/c2_c3`
stage, standard-Worker boolean, recognized complete/failed result status,
inert deployment status, integer-zero startup counts, false qualification
flags, integer ABI 1, actual mapping/read-span availability and
`simulation=false`. A failure status is admissible provenance for a failure
record, not an acceptance oracle. Negative CPU tests reject a wrong/omitted
pin, changed library/source bytes, altered loaded source or Worker identity,
nonzero or boolean startup counters, incorrect ABI/schema/stage and simulated
or unmapped Native state. The new pin still does not rehash a compiler receipt
or extend any model, CANN or hardware qualification. Source84's C3 failure
remains unchanged; the root must rerun this reader over the same originals to
obtain an updated provenance result.

This commit is an audit/CPU adaptation. It does not claim that source84's NPU
C3 succeeded or that E5 was collected. The actual source84 `POSTWRITE_APPLY_4`
failure remains for original-ABI review; a source-code error number alone is
not a substitute for its request, target and Native event joins.
