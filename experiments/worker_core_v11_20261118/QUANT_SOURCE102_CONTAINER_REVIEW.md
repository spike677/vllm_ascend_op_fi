## The remaining semantic gap

The current evidence does **not** assign a named GWS argument to a container.
It records creator inputs and the fresh returned handle. It does not record
which actual GWS function/version accepted that handle, the relevant scalar
flags, its executor registration, workspace or execute call.

In particular:

- GMM1 has 26 real public windows but no calls to these four APIs. This neither
  proves nor disproves the suspected single-tensor Native API.
- GMM2's 14-list/one-IntArray pattern is compatible with reviewed header
  candidates, but does not select a version. V4, V5 and WeightNz must not be
  equated solely from a creator count or Python operator name.
- Each unpermute window creates a nonempty IntArray although the actual public
  `restore_shape` argument is `None`. Its integers have no recorded GWS slot.
  The reader deliberately does not interpret them as a restore shape or route
  permutation; large integer values are not evidence of either meaning.
- Member matching to current tensors is useful object evidence, but it does
  not prove that an opaque list still contains those members at GWS or that
  its descriptors remain alive. Saved descriptor pointers are never read later.

## Minimal next join, proposed and not implemented

Start with **the actual GMM2 GWS/execute pair**, reusing this bounded private
proxy and lifetime journal. Do not implement a general resolver interceptor or
grant graph rows from creator success. The exact API must first be selected by
an observed typed entry or by a source/ELF call-site audit that is then checked
at that entry. The actual stock wrapper has recorded caller offsets 15,422,900
for list creation, 24,465,780 for its empty IntArray creation, and destroy calls
around 24,400,204–24,411,868 in the pinned `libtorch_npu.so`. These provide a
bounded static investigation range; they are not themselves a GWS-version
certificate. The known SDK headers are already available and must be checked
byte-for-byte for whichever candidate is chosen.

The proposed additive receipt needs only:

1. Current public scope token, actual process/thread, source/operator sequence,
   actual GWS API ID, real function/caller PCs and exact loaded-image profile.
2. Each **named typed GWS container argument**: actual handle, current live
   creator registration, original member snapshot digest and current public
   size getter. Missing, already destroyed, wrong-kind or ambiguous
   registrations reject. Individual tensor formals such as `groupList` are
   captured from the actual current GWS parameter using public SDK getters,
   not filled from Python. Preserve format29/rank5 and all actual scalar flags.
3. Original GWS return/status, actual executor pointer plus fresh registration,
   required workspace, and one actual execute entry/return with that same
   registration, actual workspace capacity and stream. An executor address
   reused for a later GWS is a new lifetime. All calls remain in the independent
   denominator; no helper call is hidden or invented.

The registry join records which creator result was passed to a named GWS slot.
It must not silently assume that the opaque container owns immutable copies or
that its saved descriptor pointers remain live. If the fixed SDK creator
contract and actual descriptor lifetime do not establish that condition, stop
at the handle join and report the specific missing lifetime evidence. Do not
read private layouts or dereference a saved descriptor after its verified
lifetime. Preserve original calls and computation unchanged.

Success means the 26 actual GMM2 pairs, all their named container registrations,
current scalar/group-list formals and execute lifetimes reconcile, with the
complete 135 denominator and healthy cleanup. Zero matches, a different API,
stale/unknown membership, unbounded metadata, missing prepare/execute, or an
owner/stream ambiguity is an explicit stop with originals preserved. Even that
success is still an input to row proof, not a fault lease.

For the eventual token-to-request result, the same current request must then
join routing output/index/count producer objects through GMM1 and GMM2 to the
actual unpermute inputs/output and exact implementation semantics. Existing
`TokenRouteProof` arithmetic can be reused on **current** bounded integer
snapshots once those Native joins exist; old source87/source93 snapshots cannot
authorize this Worker. The group/count mode, M-axis preservation, inverse-index
direction and same-request weighted reduction must all be established before
binding rows. Unknown edges retain all 125 unresolved candidates. Only a
complete newly qualified set can enter the existing CoverageSession C2 once
path, then pass the original live C2 object to bounded C3; no new Core state
machine or JSON proof reuse is proposed.
