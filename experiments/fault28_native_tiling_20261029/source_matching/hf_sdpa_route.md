# Stock HF SDPA → FA candidate, source review

The installed Qwen3 model has a native SDPA path that is source-supported to reach **FlashAttentionScore** on this 910B4 configuration. No model or NPU computation was executed for this review. This is a candidate for runtime calibration, not proof of the selected kernel or a fault result.

The installed versions are Transformers 5.5.4, PyTorch 2.10.0, and torch-npu 2.10.0.post4. The installed torch-npu `git_version` is `5dd8ef3f9b375b5ae4a83538d5785754148c3302`; its [official submodule tree](https://github.com/Ascend/pytorch/tree/5dd8ef3f9b375b5ae4a83538d5785754148c3302/third_party) selects op-plugin `8b9c8534fa41eff367a41c155843daa530ab3a08`. Exact local and upstream file hashes are recorded in `hf_sdpa_route.json`. Binary strings and generated declarations corroborate this route; this is not a reproducible-build assertion.

Installed `modeling_qwen3.py:273–285` selects `ALL_ATTENTION_FUNCTIONS` from the model configuration. `sdpa_attention.py:56–100` uses the original PyTorch functional SDPA; it enables GQA for a missing mask and contains an Ascend-specific conversion of additive masks to boolean. No replacement attention implementation is necessary.

For [op-plugin SDPA, lines 291–348](https://github.com/Ascend/op-plugin/blob/8b9c8534fa41eff367a41c155843daa530ab3a08/op_plugin/ops/opapi/ScaledDotProductAttentionKernelNpuOpApi.cpp#L291), the FP16/BNSD/boolean-or-missing-mask branch selects FA before the FIA or math branches. Qwen's 16 query heads, 8 KV heads, and head dimension 128 satisfy its head and dimension conditions. On 910B, the branch calls `npu_fusion_attention_v3`. [Its implementation, lines 2053 and 2291–2295](https://github.com/Ascend/op-plugin/blob/8b9c8534fa41eff367a41c155843daa530ab3a08/op_plugin/ops/opapi/FlashAttentionKernelNpuOpApi.cpp#L2053), dispatches the BNSD/no-sink/no-variable-length-input case to `aclnnFlashAttentionScore`.

For eager unpadded full prefill with no KV cache, the expected SDPA inputs are Q `[B,16,S,128]`, K/V `[B,8,S,128]`, FP16, missing mask and `is_causal=True`. The C++ path constructs the compressed causal boolean mask, selects sparse mode 2, `pre_tokens=INT_MAX`, `next_tokens=0`, and `inner_precise=0`. These remain runtime observations to verify. If the actual HF interface supplies an explicit mask, its GQA repetition and native sparse/precision settings differ and must be reported.

`sdpa_kernel(SDPBackend.FLASH_ATTENTION)` is present in the installed official PyTorch API. **Its flags alone are insufficient to certify the native kernel.** The [NPU choice function](https://github.com/Ascend/op-plugin/blob/8b9c8534fa41eff367a41c155843daa530ab3a08/op_plugin/ops/opapi/FusedSdpChoiceKernelNpuOpApi.cpp#L21) returns `OVERRIDEABLE=4`; the NPU SDPA fallback does not recheck the math-enable flag after its FA conditions fail. The candidate probe requests the official FLASH-only context and records actual flags, but acceptance still needs CANN's selected and launched FA operator for every layer. A successful Python call or context entry is not native coverage proof.

This candidate uses the same original **BF16 Qwen3-0.6B checkpoint loaded as FP16**, through stock Transformers. It is a separate baseline from vLLM's FP16 TND FIA execution. It neither substitutes Python attention nor claims to reproduce the historical 38B system. Native tiling capture, legal tile variation on the selected FA path, and the fault's numerical mechanism remain unverified.
