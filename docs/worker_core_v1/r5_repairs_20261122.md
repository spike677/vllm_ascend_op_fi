# r5 修复与登记要求

本轮不修改r4标签、wheel、源码包和原始回执。耗时只保留实测，不开展优化，也不放宽恢复/精度标准。

## 接口迁移

产品模式只支持 `RequestScope(mode='all')`。移除宿主逐请求调用及next-N：普通用户直接走vLLM HTTP API，Worker按实际scheduler识别请求；可信宿主通过attach/enable/status/disable/detach控制。固定金丝雀走同一推理API，不改变用户请求。详见[rc3_product_usage.md](rc3_product_usage.md)。真实HTTP蓝区验收与黄区接线结论分开，后者仍待回传。

## 39 matmul_range 的512KiB修复

旧r4黄区回传622989字节超过524288，不能算完整验收。新的`compact_matmul_calls`逐调用检查参考控制、消费与恢复，并将所有调用（包含不适用原因）按站点汇总，同时对完整有序原事件序列计算SHA256。正常阶段仍检查真实消费，不要求没有注入时出现恢复写入。故障阶段任何失败不能作为不适用跳过。四次实际前向计数与事件总数必须匹配。

导出的 `matmul_effect.call_proofs` 包括schema、call_count、ordered_calls_sha256、每站点计数/不适用原因/四次前向计数。独立review核对总数、完整事件SHA、参考数量、模型效果和OFF/health精确恢复。保留512KiB限制，未抬高上限。CPU包含1216调用、序列换序、缺调用、未恢复、普通阶段及不适用失败用例；独立总结只保留核对后的站点总数、站点清单SHA和完整有序调用SHA，避免把已核验的完整站点清单重复复制到60KB文本总结中；原回执不删改。实机结果另附。

## 预热和独立用例

`continuous_public_probe.py`预热最多6次，每次独立600秒；正式normal/fault/off/health各120秒。实际用时分别记录，预热不计入正式预算。两作用域仍必须同一组Worker。

新 `tools/run_continuous_suite.py` 给每个机制独立专用进程，机制内部保留同组Worker两作用域。失败时先统一recover并核对租约、owner、permit及binding清理；清理确认后继续下一项，最终保留全部成功/失败状态。不安全的隔离状态不能靠重启下一项掩盖，剩余项标 `NOT_RUN_UNRESOLVED_RECOVERY`。未证明恢复仍需部署负责人处理。

```bash
python tools/run_continuous_suite.py \
  --mechanisms 28 batch 18 22 39 39mr 17 \
  --evidence-root /own-new-evidence \
  --probe experiments/worker_core_v11_20261118/continuous_public_probe.py \
  --tp 2 --model /own-model \
  --source-manifest /own-release/source-review.json \
  --deployment-source YELLOW_DEDICATED_INSTANCE
```

视觉项还须按17步骤提供图片、视觉部署参数；可单独开一组suite，不能把文本配置当作视觉验收。此工具创建临时验收进程，不是现役宿主入口。运行前由可信部署按现有许可与专用实例步骤配置，示例不授予资格。

## 登记前提

运行时读取量化描述原始字节SHA256、全部实际 `*.safetensors.index.json` 文件名与SHA，以及max_model_len/max_num_batched_tokens/max_num_seqs。缺失为null/空集合/缺项原因，不补默认值。候选登记与观测都满足这些身份字段后才可能精确匹配；身份齐全仍不等于验收通过。

黄区r4只收到五份summary名称、大小与SHA，尚缺全文及逐组合完整参数。当前不新增 `YELLOW_DEDICATED_INSTANCE`。请负责人转交补充字段清单，不能用蓝区社区值填现役缺项。39mr失败后的资源清理也需补回。
