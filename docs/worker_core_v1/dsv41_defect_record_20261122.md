# V4.1 无注入正确性缺陷记录（停止适配，供部署负责人参考）

来源为11-21和11-22负责人转交的黄区纯文本，原件在仓库外归档。证据等级为黄区文本证明，不是蓝区复现。目标曾为V4.1-Flash-1017 W4A8、A3、vllm-ascend v0.32.0rc1-a3、TP8+EP、DP1、32K、单请求、chunked开启、eager、无异步/prefix/MTP、Engram cpu_offload开启。完整镜像digest与所有安装源码未齐，不用tag源码补齐。

## 现象与复现条件

- 无故障binding时，同进程重复相同5-token prompt生成8token，三次序列不同；确定性对照中的三次序列却分别与原对照同请求位置一致。3-token prompt也从第1～2个生成token分叉。
- HCCL_DETERMINISTIC、NPU deterministic level1、torch与LLM seed0没有改变这组漂移；支持“请求位置相关”而非单纯采样随机，但尚不能唯一证明具体缓存对象是根因。
- 11-22长prompt2500的三轮首步logprob均NaN。3500的详细记录为首轮首步有限、后两轮NaN；任务清单概述写“三次全NaN”，二者不一致，保留详细记录，不补造一致结论。
- 请求P/Q交换次序后输出也随请求位置变化。KV池预算从0.95改0.93，首请求token及首步局部logprob保持相同；这仅排除“这两种预算改变首请求结果”，不排除分配器/缓存复用。
- 关闭chunked prefill在两个长度配置下均启动失败，QuantLightningIndexerV2报k形状/块大小非法；这是独立部署路径问题，不把它当残留根因。

## 已知限制与静态分析

没有完整hidden/logits或逐算子首差，logprob NaN不能据此确定第一个产生NaN的算子。V4.1源码有索引哨兵过滤、新KV块清理和Engram事件同步，不能笼统称“完全未mask/未清零”。合法范围内旧索引、未覆盖的持久工作区、异步可见性仍只是候选。原始静态分析及源码指纹保留在[dsv41_state_residual_analysis.md](dsv41_state_residual_analysis.md)，不修改上游。

报告中另有W8A8大规模配置的启动、OOM和NaN结果，与上述W4A8八卡组合分开；不据此登记任何组合。黄区报告过资源范围偏差，该记录不扩散设备编号、不据其结果倒推资源授权。后续以负责人新的两组资源安排为准。

## 定性和处置

按负责人决定定性为现役软件栈正确性缺陷：不注入也会出现，可能使实际推理输出错误，并阻断统一的精确OFF/health验收。根因尚未唯一定位，不能称为DemonCATPFI引入的缺陷，也不能将故障后的残留差异按正常噪声扣除。

V4.1不再作为验收目标。停止清零工具、特性对照实验设计及兼容A/B/C继续细化；旧文档只留历史。由负责人转交部署负责人复核，本线程不要求黄区执行新操作。DeepSeek改为V4稳定版，需完整版本、权重、稳定性及inspect A～D后独立判断，不继承V4.1或V2-Lite资格。
