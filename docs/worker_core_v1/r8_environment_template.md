# r8专用实例环境与切项检查

本页为r8待交付模板，不修改冻结r7.4.1包。Qwen路线使用受审查的0.26/CANN9.1组合；Native库不能与V4另一软件栈的构建互借。A2运行结果不代表A3资格。

## 启动前

保存本次实例身份：镜像标签/可观察digest、三wheel与安装源码SHA、模型config/量化描述/全部索引SHA、硬件原名、TP和实际运行参数、Native库SHA。缺失字段按当前门禁拒绝或标记未观测，不从历史脚本补全。

Native项使用容器内受信绝对路径，库和CANN9.1目录/必要映射以只读方式绑定。不能只看版本文件：校验进程实际映射的 `libascendcl.so`、`libruntime.so` 与安装版本元数据关联。`PRODUCT_NATIVE_LOADED_CANN91_UNPROVEN`不能通过修改版本文本或跳过准入消除。

## 同容器切换测试项

1. 停止旧实例接收新请求；排空并完成当前session的disable/detach/许可撤除。若恢复未证明，按Y1维护记录处置该专用Worker组。
2. 用部署方已有服务管理入口关闭**旧API server及其Worker组**，等待退出。仅在实例明确归属且已保存PID/启动时间的前提下操作，不能用全局 `pkill python`。
3. 只读确认目标端口已无旧监听者、旧PID及其Worker均已退出，再启动新实例；不能只凭 `/health` 返回200判定新服务就绪。
4. 将新API PID、启动时间、监听端口与新启动日志对应，确认健康检查连到这一新进程；进一步核对服务模型身份及双rankWorker身份，之后才configure和安装许可。
5. 若端口仍被旧实例持有，停止切项。不要把新客户端连接旧服务得到的400/500记为当前能力结果。

实例信息只保留黄区本地；回传可用会话别名/摘要关联，不扩散机器地址和容器标识。宿主启动/CLI接线由黄区自行修改测试，公共运行时问题由Codex处理。
