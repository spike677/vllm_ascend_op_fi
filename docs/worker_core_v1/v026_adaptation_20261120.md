## 同请求执行观察器（开发增量）

新增 `v026_text_observer.py`，只供可信部署检查；没有注册成普通故障入口，也没有放开旧版多模态准入。安装前核对实际 runner/model 类型、声明方法的源码文件 SHA、NPU 设备、同步 eager 和 image/video=0；继承的 GPUModelRunner `_preprocess` 已加入独立源码清单。

实际边界为 execute_model → _preprocess → model.embed_input_ids → model forward → ExecuteModelState → sample_tokens。同一个 scheduler 对象、内部 ID、重排后的 CPU token/三轴 position、runner embedding 缓冲区前缀和模型实际参数对象必须对应；视觉模块及其子模块的实际调用会在计算前拒绝。sample 必须消费该次 ExecuteModelState，返回对应请求集合。返回的张量、logits 和调度对象均不修改。

纯文本多模态模型会经过 embedding 路径，不能套用旧版“inputs_embeds 必须为空”的准入。当前关联依据是被固定源码中的 embedding copy 与实际参数对象/存储关系，不宣称比较过 NPU 输入字节。观察结果始终 execution_authorized=false；后续 ordinary binding 还需接线和实机验收。

CPU 23 项通过（trace/真实模块 hook 17 项和已有 v026 inspection 6 项），覆盖正常生命周期、请求重排、部分 chunk、encoder/视觉参与、embedding 替换、CPU token/mRoPE 错位、旧/异构 scheduler 状态、sample 未消费和未知 runner 拒绝。这里只用 CPU fixture，无新 NPU 用时。

镜像 OCI 构建历史另外明确出现 `VLLM_TAG=v0.23.0`，因此 qwen3.8-a2 不应直接登记为 0.26；仍需读取拉取后的实际发行包版本。两个标签的前六层共有 4,641,016,981 压缩字节，但共享层不等于整个软件栈相同。

## 融合22的索引边界组件（未接入普通任务）

已按固定 `patch_qwen3_5.py` 和 `split_qkv_rmsnorm_mrope.py` 审查实现 `fault_injection/mrope_index22.py`。原路径先执行 `cos_sin_cache[positions]`，再把结果交给融合 Q/K Norm + mRoPE；该索引接收三轴 positions，融合 API 本身不再接收 positions。

组件将三个轴最后一个 token 的合法位置替换为各自第一个 token 的合法位置，在独立索引存储上执行原 `aten.index.Tensor` 一次。原 positions/cache 保持不变，非目标行精确不变；返回值不改写。它延续22的合法位置错行变体，不宣称 uint32 溢出。partial rotary 的宽度由实际 cache 给出，不假设等于 head_dim。

8项 CPU 测试通过，使用真实 PyTorch 索引核验证 B/F/OFF、错误请求对象、映射不符、缺少准入、非法范围、错误原生返回及无数值效果拒绝。尚未连接到可信模型对象作用域、新 Worker 普通任务或实际融合消费者；不能据此宣称 Q/K 变化、NPU 命中或黄区适用。需要在原模型实际调用中证明该 cache/index 输出确由融合算子消费，再登记新部署。
