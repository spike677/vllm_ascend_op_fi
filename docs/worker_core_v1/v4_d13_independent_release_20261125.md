# 库行13：router量化噪声独立D包放行方案

结论：可以与公共8分开，优先交付库行13候选。D0与噪声达标是必要条件，但不是充分条件；还须证明真实router分数的消费链，并通过实际0.30/TP8+EP产品路径的适配与验收。公共8的COMBINE_OUTPUT_ROW_JOIN_UNPROVEN不阻塞库行13，也不能因库行13通过而解除。

本方案的“13”是故障库行号，不是新增公共机制编号。复用黄区operator_output_value或value_inject的命名量化噪声变体；适配器后续由黄区维护。Codex负责所需公共运行时与部署准入。只在明确的瞬态router输出区工作，不改权重、持久scale或KV。

## 独立证据门禁

|门禁|必须证明|无需等待的公共8证据|
|---|---|---|
|D0/身份|真实硬件/软件/模型制品、源码、进程代次、绑定目标、TP/EP实际组；严格绑定守卫通过|combine输出行映射|
|G0/G1噪声|两份固定prompt、独立进程组、样本有限/token稳定/噪声上界按既定工具审查通过|dispatch辅助编码解释|
|router边界|真实非hash层、score-based选专家分支、score张量的实际生产者与选择器消费者|combine输入/输出重建|
|请求归属|该router输入/score行对应当前请求及token；SP切分、有效行清楚|combine之后的行归属|
|效果|分数变化、实际top-k专家ID/权重变化分开报告；最终top-5 logprob效果按噪声口径|公共8的请求内错位效果|
|恢复|瞬态区域安全恢复、租约资源清零、干净请求噪声金丝雀；两个owner和负例|公共8产品资格|

若只有scores变了但专家ID未变，不能宣称“选错专家”。权重变化与ID变化分别记录；未达到命名变体要求的现象如实判未通过，不能用公共8效果代替。不要求token必须改变。

## 0.30源码审查发现

官方候选[deepseek_v4/model.py](https://github.com/vllm-project/vllm-ascend/blob/v0.30.0/vllm_ascend/models/deepseek_v4/model.py)中，前num_hash_layers层可走hash专家选择，应选实际分数路由层。非内部router分支直接F.linear(router_input, gate.weight)，未必调用gate.forward；只给gate模块挂hook可能零命中。内部router分支传入名为router_logits的对象可能仍是hidden，必须继续读实际FusedMoE/选择器源码，不能根据变量名改写。

因此需要D1证明：实际分支和源码SHA、产生scores的位置、选择器如何读取它、输出expert_ids/weights如何进入真实dispatch。r2记录MoE路由整数和元数据，但不记录浮点scores/consumer完成事件；若不足，采用[定点单B档](v4_d1_targeted_capture_20261125.md)，一次补足router与公共8各自的缺项，不要求公共8同时达标。

## 产品路由与发布边界

现有外部provider v1的已审查文档范围是0.26、同步eager、单chunk，未覆盖本次0.30 TP8+EP；通用产品默认max_context=1024，也不能承载本次2500–4092 token的标定请求。D路线必须显式适配运行时边界、实际参数范围、动态请求归属和噪声金丝雀，不通过填许可或复用Qwen精确金丝雀假装完成。

只在真实调用的rank触发：副本输入对应一致命名规则，分片只作用本rank真实片段，EP无调用的rank不制造调用；条件性路由点不插全组通信。故障改变路由属于预期，不强制故障调用清单等于基线。所有rank仍在共同控制边界汇总八项计数、changed_elements、消费者、恢复及失败。

D13候选包门禁：
1. 固定0.30/CANN9.2.1/模型制品/TP8+实际EP身份与命名变体；其它组合关闭。
2. 真实router site及请求映射审查通过，CPU fixture与多rank失败恢复测试通过；可移植性验证明确不冒充V4 A3资格。
3. 自包含依赖、源码清单、影响分析、安装检查、A3双owner产品执行单与文本提取齐全。
4. A3执行时真实请求持续触发，负例结构化拒绝且引擎存活；区域/资源/金丝雀恢复，效果超过合格噪声边界。
5. 结果审查后才登记产品组合。候选发行不等于可免许可正式使用。

优先顺序：D0/G0/G1审查 → 库行13 router最小证据/专属产品路由 → D13候选交付 → A3正式验收登记。公共8独立推进映射与适配；不等待它闭合才交D13。如果D1已足够则不补采；若router证据或产品门禁缺失，就明确缺项，不仅凭噪声合格发可执行包。当前尚未收到本轮D1/G0/G1，不宣称D13已就绪。
