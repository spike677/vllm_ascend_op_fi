## 对象清单与清理边界

|状态类别|需要识别的实际对象|允许的接口/条件|禁止操作|
|---|---|---|---|
|主 KV / MLA latent / 压缩 KV|runner 实际 cache group、层、块、组件与 tensor storage|已审查 runner zeroer / `_zero_block_ids`；空闲状态下按实际布局完整枚举，量化 scale 按原接口重建|猜测页布局、只清一块却宣称整池清理、清共享前缀而仍保留调度映射|
|Indexer 索引及长度|QLI 输出、后处理 indices、有效长度、复用 workspace|可信对象句柄与实际 dtype/shape；索引无效值通常为 -1，长度为0，按消费接口初始化|统一 `zero_()` 将无效索引变成合法 key0；自行改变合法 key 集合|
|压缩器临时区|压缩器持久 workspace、边界计数与待完成事件|必须说明所有者、有效范围及下一请求是否完整重写；同 stream 完成后使用已审查初始化规则|覆盖仍被异步消费者读取的存储|
|Engram 非 KV 状态|lookback/history、hash/lookup 输出、ready/prepare 事件、暂存区|只列入可证明为请求临时状态的对象；完成消费、释放事件并按接口重建|清零 UVA 注册的 embedding 表、模型权重、CPU offload 的参数页或任意裸地址|
|调度/缓存管理|请求表、block 分配表、prefix/encoder/connector 状态|无 active/queued 请求；无 prefix cache、无 connector；各 rank 一致到控制边界|张量清理后留下旧 metadata、直接改私有计数假装资源归零|

对象必须以真实运行时发现为准。清理器先输出 inventory（rank、owner、对象角色、device、dtype、shape、存储身份、区间、初始化规则、源码指纹），不接受外部任意地址。未列入清单的状态不会被称为已隔离。清理在所有 rank 都到达的空闲控制边界执行，不能在条件性算子命中点插入 collective。任一 rank 失败，整组不进入下一阶段。

## 三个候选方案

**A：KV 及其配套索引状态隔离。** 参照进程和故障验收进程每阶段都执行同一清理：主 KV、MLA/压缩 KV、与这些页配套的 indexer 索引/长度。先仅做无注入实验，确定清理是否改变正常语义。必须同时记录 Engram 等未清理状态的存在，不能称为全状态复位。

**B：A 加非 KV 请求状态。** 在 A 的清单上扩展到经审查的 Engram lookback、hash/lookup 输出、压缩器工作区和事件。只清请求临时状态，保留参数表。任务书在 A 的示例中也列举了 Engram，因此最终选择时必须同时固定对象清单：A/B 名称本身不能作为“已清理哪些对象”的证据。若负责人要求 A 已包括 Engram，则 B 只能代表清单中另行发现、已审查的非 KV 状态，不能重复命名后声称新增覆盖。

**C：位置对齐的受限恢复口径。** 两个独立、同身份进程分别执行 normal×4 和 normal/fault/off/health，按请求位置比较。只比较无注入对照能够重复的输出部分，掩码/字段必须在看 fault 结果之前由独立 normal 对照冻结；报告完整输出中被排除的数量和位置。注入区域字节恢复、对象/租约资源清零仍必须完整满足。若故障改变残留状态，后续差异可能是故障延续；不能归入正常噪声、不能事后排除，更不能据 C 宣称完整 hidden/logits 精确恢复。登记必须带受限口径标注，需负责人明确批准。

这三种方案均尚未启用。只在负责人根据黄区对照选择后编写最终故障验收步骤和登记字段。

## 无注入的判别实验

由负责人转交，暂不要求黄区自行执行新操作。Codex 提供的清理器必须在真实源码身份和对象清单审查后才允许 apply；当前先交设计，不以通用递归 `zero_()` 脚本代替适配。

1. 固定测试制品、TP8+EP 拓扑、32K 预算、单 chunk、固定 prompt/token。保留正常重复对照的完整 hidden/logits 指纹、非有限计数、token和rank身份。
2. 新进程 R0 运行第1次请求；独立进程 R1 连续运行 N 次无清理请求，确认先前残留现象的可重复范围。不要将不同位置的输出直接对比为故障恢复失败。
3. 新进程 R2 每请求前按 A 清理，运行 N 次；R3 使用相同清理但不同固定正常请求顺序。比较同进程第 N 次与新进程第1次，分别报告完整相等、差异元素、非有限、token。
4. A 若不足，再由负责人批准 B 的完整对象清单后执行。A/B 的每次清理前后均记录无活动请求、在途事件完成、对象身份未变/受控重建、区间覆盖和资源计数。
5. 语义对照：对本来稳定的合法正常输入，比较原路径与清理后路径；索引合法集合、有效 KV 和 logits 均不得因清理而改变。仅“清理后稳定”不足以证明正确；可能只是把本来错误读取的旧状态换成稳定零值。需要报告这种情况，不能拿稳定性替代正确性。
6. 文本回传包含每个进程身份摘要、每请求位置、清理清单版本与SHA、rank状态、结果指纹与差异摘要、原回执文件名/字节数/SHA、完整拒绝码。原件留黄区，蓝区按文本证明记录。

清理工具实现的前置条件仍缺：黄区真实对象 inventory、实际初始化接口/源码指纹、事件和空闲边界证据；这些不得由 tag 源码或默认值补齐。届时提供 CPU 替身测试：参数表拒绝、未知状态拒绝、索引哨兵规则、跨rank部分失败、活跃请求拒绝、地址复用和清理后metadata一致性。
