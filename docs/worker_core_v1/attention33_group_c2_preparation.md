# Fault33 all-target isolated C2 candidate

This increment connects the separate `tnd_page16_arch22_group_s2_256` package
to the existing public `33.paged_decode` resolver through the exact trusted
`GroupEffectsNativeCall` type. It does not change the registry, Host, Runtime,
exporter, Native kernel arithmetic, SplitCore formula or S2 fault definition.
The earlier normal-only driver still rejects fault phases. This is CPU-tested
candidate code, not a device qualification or permission to reuse old results.

The source105 accepted single-site function/OFF result keeps its original
scope. Source108's interrupted private normal result is incomplete. Neither
result authorizes any target in this protocol. The final source, wheels,
observer, model, new group vendor/build and execution configuration must first
complete **their own** stock/private normal pair: five phases, 140 distinct
target pairs, 435 complete payload pairs, and original scoped Native evidence.
The Worker reruns the independent raw normal reader and creates a process-local
typed object. A saved report, its status, or its boolean is never live authority.

The actual model's 28 Attention objects are discovered by the existing adapter;
the user supplies no layer names. Each of 60 requests preserves all 56 natural
prefill/decode calls. All 28 decode targets are supported in the explicit
Q1/KV1025/page16/FP16 scope. All 28 actual prefill calls remain in the denominator
with `ACTUAL_PREFILL_OUTSIDE_Q1_S2_SCOPE`; matching decode calls cannot be dropped
because an input or proof is missing.

Three actual controls establish current Worker/module/implementation/cache
objects and current Q/valid logical KV/mask/page-table/slot bindings for every
target. Then 28 isolated F/OFF pairs change one actual target at a time, followed
by a complete cleanup-health request. Every F gets an actual independent call
ticket, current-input recheck, one-use permit and host admission SHA. The other
targets still execute once and remain recorded. An upstream changed input is
not silently accepted for later F: the intervening full OFF must restore it.
Immediate Attention numerical change is required for a HIT; model-logits
propagation is recorded separately and is not an additional HIT requirement.
The runtime rehashes both complete 4096-byte FP16 operator-output files and
compares every value using the CPU standard library; a signed-zero-only byte
change is not a numerical HIT. This introduces no additional model/device call.

The three controls and every OFF/health request require all 87 full payloads
to equal the new normal baseline. Read-before valid KV and masks remain
source-bound hashes; matching full post-consumer logical KV bins are retained
and independently rehashed. This limitation is explicit. Each F preserves its
actual POD, ELF registration, launch key, owner/thread/token, current public
input/consumer and original-once receipt. No allocator or shape guess substitutes
for object/storage joins.

The runtime records a live `CoverageSession` over all 56 candidates and selects
all 28 eligible decode targets once. It holds an admitted decision through the
actual consumer and complete model return. The original C2 object can be issued
only after full OFF, health, Native drain, and zero owned hooks/API wrappers/input
references. Public reservation remains held until unregister. An uncertain F
is never retried; its owner and original error remain until a fresh same-Worker
OFF and health finish. Failed experiments cannot issue C2. C3 stays disabled:
current propagated-input and stock-owner exact-normal authority are not proven.
E5 and cross-model/device/shape qualification are not granted.

Cleanup checks protocol/recovery readiness before removing observers or input
references. An early disable after the three controls records the incomplete
protocol, retains those resources, and permits only fresh recovery OFF and
health requests. Once they complete, disable/unregister/detach can release the
owner; the original error remains and no C2 proof is issued.

## Fixed cost and capacity gates

The normal preparer stays at 128 MiB per runtime log. Only this exact group
source/build and the live normal object's own attempt can create the 512 MiB
runtime-log scope. Tensor, ELF, JSON-line and per-request capture bounds do not
increase. Each capture is limited to 128 MiB; all 60 capture references total at
most 7.5 GiB. The complete original log and all registration generations remain.
No user flag can raise the cap or the 1800-second case budget.

The live C2 collector enforces the normal collector's separate per-request
limits before reading the capture or completing a request: capture JSON at
most 128 MiB, and at most 1024 other files totaling 512 MiB. Root/request
directory identities are retained from creation. Collection rejects symlinks,
replacement, growth, and disagreement between saved JSON and the actual
in-memory capture; opened-file and path identities are checked before/after
the bounded read. A second inventory check precedes the completion receipt.
Refusal leaves the originals and live recovery owner intact and cannot issue C2.

The resource plan uses all five complete new normal phase measurements. It
counts initialization and ordinary health once, uses the maximum observed
phase increment with a factor of two, includes non-window logging and three
recovery requests, and extrapolates cumulative prefix rehash cost. Disk covers
all payloads, captures, boundaries, host logs, binaries and recovery margin.
Memory covers the projected parsed log and retained captures. At every F
request and immediately before Native admission, actual elapsed time, log
prefix, free disk and host/cgroup available memory are checked again. Memory
uses the greater of normal and live projected requirements. Completed actual
phase growth/timing above the conservative normal bound stops new F. Initial
Worker setup/raw-normal replay time is included in live elapsed time.

`NO_F_CAPACITY_REFUSED` and `NO_F_TIME_REFUSED` are preserved failures. They do
not extend the case budget, retry F, or suppress recovery. A resource receipt
alone has `fault_authorized=false`; its SHA is only one part of the actual
current-input permit. Query returns recorded summaries without refreshing the
log, sampling counters or issuing model/Native calls.
