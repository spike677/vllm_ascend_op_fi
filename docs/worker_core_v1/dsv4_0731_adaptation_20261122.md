## 8 的行错位代理实现状态

新增 `fault_injection/sites/mc2_output8.py`：先执行原combine，全部通信参数原样透传；仅在真实返回张量上按当前请求行组循环错位。padding行和单行组不变；无调用的EP rank不制造调用。消费者必须实际读取整个返回对象；视图、别名、原地覆盖、未知消费点均拒绝，保留租约供失败恢复。使用现有RegionLeases确认设备消费完成再恢复完整字节。

CPU夹具覆盖动态请求组、padding、透传通信参数、两作用域消费者与精确恢复、无调用rank、单行decode、原地消费者拒绝。**这只完成公共代理与受控结构夹具，不是V4或V2-Lite实机验收。** 实际scheduler join仍由受信适配层提供，公共入口没有注册此候选。已验收V2-Lite TP2路径是AllGather/unpermute且EP关闭，不能把它的旧通过结果当作MC2输出代理的参照验收；需要单独确认可运行的MC2+EP组合和消费者后才能补测。旧8实现保留。

## 给负责人转交的稳定性验证步骤

在同一专用实例、同一权重/软件栈、确定性参数下准备固定A/B/C三个长输入，分别至少2500 token，输入+生成不超过4096，单chunk，固定生成长度。先记录实际token数组的SHA及长度，不用字符数代替token数。

1. 同一进程连续A/A/A，记录每次完整token、logprob指纹、有限值计数及实际单chunk调度。
2. 不重启、不清缓存，人为改变请求顺序：A/B/A/C/A，再B/C/B/A/B。比较同一输入的所有出现位置。
3. 新进程各执行一次A/B/C，再与同进程结果比较；同时记录每个阶段实际启动/模型身份。
4. 任一不一致则保留原结果，判为稳定性未成立；不放宽恢复标准，不以跨进程一次一致代替同进程稳定。

只在上述基线成立后设置同样长度的产品金丝雀。请补充文本：prefill/decode分别计数；运行时已加载的CANN库路径、版本来源与SHA；候选源码SHA；部署量化与索引SHA和完整参数；清理后资源计数。目录软链接8.5.0/8.1.RC1/8.5.1不能证明实际加载版本。本页由负责人转交，本轮未向黄区直接发送操作请求。
